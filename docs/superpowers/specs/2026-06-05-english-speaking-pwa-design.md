# 个人英语口语练习 PWA 初版程序设计方案

日期：2026-06-05

## 1. 项目定位

本项目是一个面向单人自练的英语口语输出训练器，目标用户是读、写、听输入能力较强，但口头输出不够自动化、不够流畅的学习者。

初版不做通用英语学习 App，也不做泛聊天机器人。核心目标是让用户每天完成 10 到 20 分钟结构化开口训练，并能看到自己的停顿、填充词、说话长度、任务完成度等趋势变化。

产品的一句话目标是：

> 做一个不用 LLM 也能练、联网后更强、最终能在 iPhone 主屏幕使用的个人口语训练 PWA。

## 2. 设计原则

### 2.1 任务型训练优先

自由聊天容易让用户陷入“想法很多但嘴跟不上”的状态。初版要把口语输出拆成小任务：句型启动、看图描述、半脚本情境对话、高级约束表达。每个任务都有时间限制、目标结构和可检查条件。

### 2.2 本地优先，云端增强

训练入口、题库、录音、回放、历史记录、基础趋势应优先保存在本地。云端只用于需要更强能力的环节，例如 ASR 转写、TTS 播放和后续 LLM 反馈。

这样做有三个原因：

- 降低云服务成本。
- 弱网或离线时仍能完成基础训练。
- 个人语音数据默认留在设备侧，减少不必要上传。

### 2.3 规则引擎先于 LLM

系统核心不能依赖 LLM 才能运行。任务定义、对话状态、约束检查、复盘指标都应先做成规则化结构。LLM 后续只作为增强层，用来生成更自然的 NPC 文案、给出更细的反馈或扩充题库。

### 2.4 关注流利度，不先追求发音评分

初版优先衡量：

- 是否能快速开口。
- 是否能连续说满指定时间。
- 是否频繁长停顿。
- 是否大量使用 filler words，例如 `um`、`uh`、`you know`。
- 是否能命中指定句型、连接词和任务 slot。

初版不做音素级纠错、美音/英音评分、音标可视化。

## 3. 初版核心功能

### 3.1 今日训练首页

首页展示当天训练入口和最近表现摘要。

功能包括：

- 今日推荐训练模块。
- 本周训练分钟数。
- 最近 7 天练习趋势。
- 一键进入训练。
- 历史记录入口。

首页风格应像训练台，而不是社交软件或聊天软件。

### 3.2 句型启动训练

目标：解决开口慢、第一句话卡住、句式启动单一的问题。

交互方式：

- 系统给出一个 starter，例如 `One possible explanation is...`。
- 用户在 10 到 20 秒内录音回答。
- 系统记录是否命中 starter、是否说满时长、长停顿次数、填充词数量。

最小任务结构：

- `id`
- `starter`
- `topic`
- `durationSec`
- `requiredConnectors`
- `difficulty`

初版不判断内容是否深刻，只判断是否完成指定输出动作。

### 3.3 看图描述

目标：训练从画面信息到连续英文表达的组织能力。

交互方式：

- 系统从本地图片题库展示一张图。
- 用户选择 30、45、60 秒任一档位。
- 任务要求通常是：先总述，再描述 3 个细节，再给 1 个推测。
- 录音后进入复盘。

每张图片配套一个本地 JSON 元数据：

- 图片路径。
- 主题标签。
- 推荐表达框架。
- 目标细节点。
- 难度。
- 可选提示词。

初版不需要模型理解图片。系统只需要用图片元数据和转写文本检查关键词覆盖、表达框架命中和输出时长。

### 3.4 半脚本情境对话

目标：训练真实场景中的回应和推进能力，避免只会短答。

初版场景建议：

- 点咖啡或点餐。
- 问路或求助。
- 会议中表达进展。
- 项目讨论中提出问题和建议。

实现方式：

- 每个场景是一个有限状态机。
- NPC 每轮给出固定或半随机文案。
- 用户录音后经 ASR 得到文本。
- 规则引擎根据关键词、短语和 slot 判断下一步状态。

示例 slot：

- `drink`
- `size`
- `hot_or_iced`
- `problem`
- `suggestion`
- `deadline`

系统不需要理解所有自然语言，只要能判断用户是否把当前任务推进下去。

### 3.5 高级约束表达

目标：训练更高阶的英语组织动作，而不是只堆简单句。

任务形式：

- 给用户一个话题和立场。
- 要求本轮必须命中特定表达策略。

常见约束：

- 让步：`To some extent...`、`I agree that..., but...`
- 比较：`Compared with...`、`In contrast...`
- 举例：`For example...`
- 因果：`One reason is that...`
- 总结：`Overall...`

初版反馈重点：

- 是否命中 required markers。
- 是否说满指定时间。
- 是否出现明显卡顿。
- 是否有重复重启。

### 3.6 复盘与趋势

每轮训练结束后展示即时复盘。

复盘指标：

- 录音总时长。
- 有声时长。
- 起说延迟。
- 长停顿次数。
- 停顿占比。
- filler 数量。
- 转写词数。
- 估算 speech rate。
- starter / marker / slot 命中情况。
- 推荐重练片段。

趋势页展示：

- 每日练习分钟数。
- 最近 7 天 pause ratio 趋势。
- 最近 7 天 filler ratio 趋势。
- 最近 7 天 mean length of run 趋势。
- 各任务类型完成次数。

## 4. 非 LLM 核心原理

### 4.1 录音

浏览器通过 `getUserMedia` 获取麦克风权限和音频流，通过 `MediaRecorder` 生成音频 Blob。

录音数据初版默认存入 IndexedDB，包括：

- 音频 Blob。
- 任务 ID。
- 录音开始和结束时间。
- 设备侧计算指标。
- ASR 文本和云端分析结果，如果有。

### 4.2 本地静音和停顿检测

初版使用 Web Audio API 的音量能量分析实现基础 VAD。

计算过程：

1. 将录音期间的音频帧按短窗口分析。
2. 根据能量阈值判断有声和静音。
3. 连续静音超过 700ms 记为长停顿。
4. 得到有声片段列表。

后续如果需要更稳，可以引入 `@ricky0123/vad-web` 或 Silero VAD，但初版先不增加模型依赖。

### 4.3 流利度指标

最小指标定义：

- `durationSec`：任务总时长。
- `voicedSec`：有声片段总时长。
- `pauseRatio`：静音时长 / 总时长。
- `longPauseCount`：超过 700ms 的静音次数。
- `speechRate`：ASR 词数 / 总分钟数。
- `articulationRate`：ASR 词数 / 有声分钟数。
- `meanLengthOfRun`：每个连续有声片段平均词数。
- `fillerCount`：填充词命中次数。

这些指标不代表口语能力总分，只用于个人趋势比较。

### 4.4 规则检查

规则检查分三类：

- 文本模式：检测 starter、marker、filler、连接词。
- slot 规则：检测情境对话中的关键信息是否出现。
- 任务完成规则：检测是否达到时长、轮次、结构要求。

规则引擎输入：

- 任务定义。
- ASR 文本。
- 音频指标。
- 当前对话状态。

规则引擎输出：

- 完成度。
- 命中项。
- 未命中项。
- 下一轮任务建议。

## 5. 技术架构

### 5.1 前端

推荐技术栈：

- React
- TypeScript
- Vite
- vite-plugin-pwa
- React Router
- IndexedDB，优先使用 Dexie 封装
- Web Audio API
- MediaRecorder
- Vitest
- Playwright WebKit

选择原因：

- Windows 开发体验稳定。
- Vite 支持 React + TypeScript 模板，启动和构建速度快。
- PWA 能通过 Safari 添加到 iPhone 主屏幕。
- IndexedDB 适合保存音频 Blob 和结构化训练记录。
- Playwright WebKit 可以尽量提前发现 iPhone Safari 相关问题。

### 5.2 本地数据结构

主要对象：

- `TaskPack`：题包，包含 starter、图片任务、对话脚本、约束任务。
- `PracticeSession`：一次训练会话。
- `PracticeTurn`：一次录音轮次。
- `AudioRecord`：录音 Blob 与元数据。
- `AnalysisResult`：本地和云端分析结果。
- `TrendSnapshot`：按天聚合的趋势数据。

初版所有数据先存本地 IndexedDB。云端同步不是初版必要功能。

### 5.3 后端

后端只做轻量代理和密钥保护，不承载核心训练逻辑。

初版后端 API：

- `POST /api/asr`：上传音频，返回转写文本和可用时间戳。
- `POST /api/tts`：输入文本，返回 NPC 音频。
- `POST /api/llm/evaluate`：后续可选，输入转写和指标，返回 JSON 反馈。

后端职责：

- 隐藏云服务密钥。
- 统一不同云厂商接口。
- 控制请求大小和频率。
- 记录最小必要错误日志。

## 6. 部署方案

### 6.1 首选：腾讯云 CloudBase

推荐组合：

- CloudBase 静态网站托管部署 PWA 前端。
- CloudBase Run 或云函数做代理 API。
- 腾讯云 ASR/TTS 作为默认语音服务。

理由：

- CloudBase 文档当前支持 React/Vite 项目部署。
- 静态托管提供 HTTPS，满足 PWA 和麦克风权限要求。
- 与腾讯云 ASR/TTS 在账号和网络链路上更统一。
- 对个人开发者比自建服务器更省心。

### 6.2 备选：阿里云 OSS + 函数计算

适合已经有阿里云账号或后续想接阿里百炼的情况。

优点：

- 基础设施成熟。
- 函数计算适合做 API 代理。
- 阿里云智能语音和百炼模型服务可统一管理。

缺点：

- 初次配置项通常比 CloudBase 更分散。

### 6.3 备案策略

初版建议先不绑定自定义域名，直接使用云平台提供的 HTTPS 域名测试。

如果后续使用中国内地节点并绑定自定义域名，通常需要按服务商要求完成 ICP 备案。这个事项不进入第一阶段开发。

## 7. 候选服务

### 7.1 ASR 语音识别

首选：腾讯云 ASR。

适用理由：

- 支持一句话识别、实时语音识别、录音文件识别等形态。
- 官方产品页显示有新用户免费体验资源包。
- 支持英文识别和中英混合相关能力。
- 与 CloudBase 后端代理组合顺。

备选：科大讯飞语音听写流式 WebAPI。

适用理由：

- 适合 1 分钟内即时语音转文字。
- 中英文接口明确。
- 对短句训练和快速反馈友好。

备选：阿里云智能语音交互。

适用理由：

- 官方提供 WebSocket 实时语音识别文档。
- 如果后端和 LLM 走阿里云，集成路径顺。

### 7.2 TTS 语音合成

首选：腾讯云 TTS。

适用理由：

- 支持中文、英文和中英混读。
- 官方购买指南显示有通用语音合成免费额度。
- 初版 NPC 文案短，字符消耗可控。

备选：阿里云 TTS 或讯飞 TTS。

使用条件：

- 如果 ASR A/B 测试发现某家整体体验更好，再切换或混搭。

### 7.3 LLM

初版不强依赖 LLM。第二阶段后可选接入。

首选候选：DeepSeek API。

适用理由：

- 适合低成本 JSON 评价器。
- 可用于生成重练建议、改写模板和新题目。

其他候选：

- 阿里百炼 / 通义千问。
- 腾讯混元。
- 百度千帆。
- 智谱开放平台。

LLM 接入原则：

- 所有 LLM 调用必须走后端代理。
- 输出必须约束为 JSON。
- 只用于反馈增强和任务扩展，不控制核心训练流程。

## 8. 分阶段实现路径

### 阶段 1：PWA 壳子与本地录音

目标：

- 建立 React + TypeScript + Vite 项目。
- 配置 PWA manifest 和 service worker。
- 实现首页、训练页、复盘页基础路由。
- 实现录音、停止、回放。
- 将录音和训练元数据保存到 IndexedDB。

验收标准：

- Windows 浏览器可打开并录音。
- iPhone Safari 可打开 HTTPS 版本并授权麦克风。
- 录音结束后可回放。
- 刷新页面后历史记录仍在。

### 阶段 2：任务系统与本地题库

目标：

- 实现句型启动训练。
- 实现看图描述训练。
- 用 JSON 定义题库。
- 实现计时器和任务完成状态。

验收标准：

- 用户能连续完成一组 5 到 10 分钟训练。
- 每轮训练都能生成结果页。
- 不联网也能完成基础训练。

### 阶段 3：本地流利度指标

目标：

- 实现基础 VAD。
- 计算起说延迟、长停顿、停顿占比。
- 建立趋势页。

验收标准：

- 每次训练后显示基础指标。
- 最近 7 天趋势可查看。
- 指标计算逻辑有单元测试。

### 阶段 4：云端 ASR/TTS

目标：

- 增加后端代理。
- 接入首个 ASR 服务。
- 根据转写文本检测 filler、starter、marker。
- 可选接入 TTS 播放 NPC 文案。

验收标准：

- 上传录音后能得到英文转写。
- 转写失败时不影响本地记录保存。
- 用户能看到文本维度的任务反馈。

### 阶段 5：半脚本情境对话

目标：

- 实现有限状态机场景引擎。
- 实现 slot 检查。
- 完成至少两个场景：点餐和会议进展。

验收标准：

- NPC 能根据用户回答进入下一状态。
- slot 未命中时能提示重说或补充。
- 每个场景有可重复训练路径。

### 阶段 6：高级约束表达与 LLM 增强

目标：

- 实现让步、比较、举例、因果等约束任务。
- 可选接入 LLM 评价器。
- 生成更自然的复盘建议和重练模板。

验收标准：

- 不接 LLM 时仍可运行。
- 接 LLM 后反馈更丰富，但不改变核心流程。
- LLM 输出 JSON 结构稳定。

## 9. 初版明确不做

初版不做以下内容：

- App Store 原生上架。
- React Native / Swift 原生 App。
- 社交、排行榜、课程商城。
- 多用户账户系统。
- 支付系统。
- 发音评分。
- 音素级纠错。
- 实时双向 voice-to-voice。
- 完整离线 ASR。
- 云端自动同步全部音频。

这些功能不是永久不做，而是初版不纳入，避免项目过早变重。

## 10. 错误处理与隐私

### 10.1 麦克风权限失败

处理方式：

- 显示权限说明。
- 提供重试按钮。
- 保留文本任务预览，但禁止开始录音。

### 10.2 录音失败

处理方式：

- 停止所有音轨。
- 显示错误原因。
- 允许重新录制。

### 10.3 ASR/TTS 失败

处理方式：

- 本地录音和基础指标照常保存。
- 标记云端分析状态为失败。
- 允许用户稍后重试上传。

### 10.4 本地存储过大

处理方式：

- 历史页显示音频占用空间。
- 提供删除单条记录和清理旧音频功能。
- 统计指标可保留，音频可删除。

### 10.5 隐私原则

- 默认本地保存音频。
- 云端只上传用户主动请求分析的音频。
- 不在前端保存云服务密钥。
- 后端日志不记录完整音频和敏感转写内容。

## 11. 测试策略

### 11.1 单元测试

使用 Vitest 测试：

- 流利度公式。
- filler 检测。
- starter/marker 命中。
- slot 规则。
- FSM 状态跳转。

### 11.2 浏览器测试

使用 Playwright 测试：

- 页面路由。
- 训练流程。
- 结果页展示。
- 历史记录保存和读取。
- WebKit 基础兼容性。

### 11.3 真机测试

使用 iPhone Safari 测试：

- 添加到主屏幕。
- 麦克风授权。
- PWA 独立窗口显示。
- 录音和回放。
- 弱网下本地训练。

## 12. 需要用户拍板的决策

### 决策 1：首个云服务主线

推荐选择：腾讯云一栈。

备选：

- 腾讯云 CloudBase + 腾讯 ASR/TTS。
- CloudBase + 讯飞 ASR + 腾讯 TTS。
- 阿里云 OSS/FC + 阿里 ASR/TTS。

影响：

- 影响后端代理实现。
- 影响账号开通和免费额度领取。
- 影响后续部署文档。

### 决策 2：初版是否接 ASR

推荐选择：阶段 1 到 3 不接 ASR，阶段 4 再接。

影响：

- 如果现在就接 ASR，反馈更完整，但会提前引入账号、鉴权、音频格式和网络问题。
- 如果先不接 ASR，可以更快做出可录、可练、可复盘的本地产品。

### 决策 3：是否保留历史音频

推荐选择：默认保留最近 30 天音频，长期保留统计指标。

影响：

- 保留音频方便复盘，但占本地空间。
- 只保留指标更轻，但无法回听旧表现。

### 决策 4：首批训练内容语言

推荐选择：UI 用中文，训练提示和表达模板用英文，复盘解释用中文。

影响：

- 中文 UI 降低使用阻力。
- 英文模板保证训练目标明确。
- 后续如果想分享给别人，可再做语言切换。

### 决策 5：首批图片素材来源

推荐选择：先使用本地低版权风险图片或自制图片，并为每张图人工写元数据。

影响：

- 手工元数据更稳定。
- 避免初版接入图像理解模型。
- 后续可扩展为用户上传图片或 AI 生成题图。
